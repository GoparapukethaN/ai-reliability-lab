# Incident response notes

An ML incident should have an owner, timeline, impact summary, mitigation, and follow-up
items. The first response should stabilize the system before deeper root-cause analysis.

## Triage

During triage, check recent deployments, data pipeline health, model registry changes,
and upstream dependency errors.

## Post-incident review

The review should identify what detected the issue, what slowed response, and what guard
would have prevented or reduced the incident.
